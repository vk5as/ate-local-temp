# Test Report content and format

Type: grilling
Status: resolved
Blocked by: 03, 11

## Question

What does a Test Report contain (including a summary cover page with the overall result and a count of steps for each `Result` value) and how is it laid out, as HTML with PDF rendered from it, and how is it produced at run end and regenerated later?
Also from "Flow control" (10): the run's stop-on-fail setting and end reason (`COMPLETED`, `PRETEST_FAILED`, `STOPPED_ON_FAIL`, `ABORTED`); every Attempt of a retried step (number, result, message, log lines), with the step's result being the last Attempt's; retried steps are flagged on the report.
Also from "Sub-schedules" (14): include header rows (Step Name, optional Step Number) group their Sub-schedule's steps and have no `Result`; they are not counted in the summary, but may show a roll-up. Every step shows its optional Step Name.
Also from "What a Test Run records" (11): reports are regenerated from the database alone (`assets/test-run-record.md`). The record gives the run fields (including UUT Type, Station name at the time and UTC offset for local times), the resolved Media Release chain, per-file checksums and mismatches, the expanded tree with headers and Operator enable overrides (`default_enabled` vs `enabled`), each action's outcome, every Attempt with its failure-prompt choice, every input value, and every log line with its level and source. End Reason may also be `INTERRUPTED`.

## Answer

Full definition: `assets/test-report-format.md`.

- **Production**: HTML and PDF are written to `reports.directory` automatically at run end. History regenerates either format for any finished run, including `INTERRUPTED`, using the current template; the footer shows both ATE versions. Files are named `<UUT Type>/<UUT Type>_<serial>_<local start>_<PASS|FAIL>` and never overwritten.
- **Format**: one self-contained HTML file from a bundled Jinja2 template, with the PDF rendered from it. A4 or Letter. A header and footer on every page with "Page X of Y". The only customisation is `reports.organisation`, `reports.logo` and `reports.paperSize`.
- **Sections**: Cover → Steps → Equipment → Configuration → Run log. There is no Actions section.
- **Cover**: doc fields, PASS/FAIL with the End Reason (naming a failed Pre-test or Post-test Action), banners for mismatches and `INTERRUPTED`, run details, Operator with a signature box and date line, a count for each `Result`, retried and override counts, and a Failures list.
- **Steps**: Step Number | Step Name with the message under it | Expected | Actual | Result. Earlier Attempts are sub-rows, inputs and overrides are noted under the name, and header rows show counts.
- **Equipment**: a new `ATE.addEquipment(name, serial, connection, calDue, notes)`, all strings, stored in a new `equipment` table and shown as a table.
- **Configuration**: only the files actually used, the releases that supplied them, and the Sub-schedule instances without `keyvals`.
- **Run log**: `INFO` and above, grouped by owner. `DEBUG` lines and Device trace never appear.
- **Record changes**: `test_run` gains `schedule_description`, `doc_title`, `doc_id` and `doc_rev`.
- **New term**: Equipment.
- **PDF engine**: handed to "Render a sample Test Report to PDF" (17).

## Comments

### Round 1, 2026-10-17

- Doc fields are stored on `test_run`, with the title falling back to the schedule name.
- Reports are written automatically at run end. Names are readable, not UUIDs.
- Regeneration uses the current template. Reports generated by Lua scripts may come later, but not in v1.
- A signature location goes next to the Operator name.
- The message goes under the Step Name in smaller type. Column order: Step Number, Step Name / message, Expected, Actual, Result.
- The log appendix is `INFO` and above.
- No Actions section. Only the files actually used are listed. A new Equipment section goes between Steps and Configuration, filled by `ATE.addEquipment(name, serial, connection info, calibration due date)`, all strings.
- Jinja2 with inline CSS, plus organisation and logo keys. A4 or Letter, with page furniture. The engine is decided by a prototype.

### Round 2, 2026-10-17

- The signature space must suit either an electronic signature or a handwritten one.
- Equipment is a domain term, separate from Device.
- `addEquipment` semantics accepted, plus a free-text `notes` argument. The Equipment table gains a Notes column.
- The cover explains Pre-test and Post-test Action failures.
- Sub-schedule instances are listed without `keyvals`.
- Step row detail accepted.

### Round 3, 2026-10-17

- The signature is a visual box only for now; there is no PDF signature field. Cryptographically signing reports to authenticate them is v2.
