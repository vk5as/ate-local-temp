Make the restart deterministic, for example by driving the progress callback, and keep it able to fail.
- [x] Windows: config JSON written by tests with raw `C:\...` paths is invalid JSON (`invalid JSON in config file`, `JSONDecodeError`). Find whether only tests do this, or whether `ate setup` or any product writer does too: a product writer must use `json.dump`. — only tests do: `config.write_config`, `cli`'s selftest and `examples/harness/run_examples.py` all use `json.dumps`, and nothing in `src/` builds a config string by hand.
- [x] Windows: tests asserting exact `ate setup` output fail on "running unprivileged; skipping group/ownership" lines; `test_a_bare_ate_set_up_takes_its_directories_from_the_config_seams` reaches the real `C:\ProgramData\ATE`: no test may touch a real system directory on any platform. — that line is only noise in the assertion message; every one of those tests failed on the invalid config behind it. The layout bug is fixed in the product, and `conftest.py` now fails any test that leaves a file in the machine's real Station directories.
- [x] Windows: `signal.SIGKILL` doesn't exist; `os.execute` holding the abort and `kill $PPID` are POSIX commands. Use platform-appropriate commands or skip with a stated reason, and say in the manuals what is POSIX-only. — the kill uses `taskkill /F` on Windows, and tolerates taskkill's "process already gone" exit code; the `kill $PPID` probe is Linux-only, and the `os.execute` hold probe runs on Windows with `ping -n 4 127.0.0.1 >NUL`. Both forms of the manuals say the command is a POSIX one, and the check reads the lines around each quote rather than the whole file.
- [x] Windows: `test_an_abort_ends_a_long_write_to_a_peer_that_stopped_reading[SERIAL|TCP|VISA]` fail with an unexpected result (`NOREPORT?`). These are 32b's tests and passed before: find out whether 35 changed behaviour or the test is flaky on Windows, and fix the cause. — 35 changed nothing here. The peer only set `SO_RCVBUF` on its listener, and a listener's receive buffer does not reach the socket it accepts: the accepted socket had the platform default, so the write drained before the abort. It now sets the buffer on the accepted socket, sends the payload in 200 logged 1 MB pieces, and fails if all of them are out before the abort. It runs on every platform; whether Windows is deterministic is only provable on a Windows runner.
